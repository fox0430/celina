# Migrating from v0.13.0 to v0.14.0

Most apps built on `App` / `AsyncApp` and the widgets need at most one change:
a branch for `InputClosed` in an exhaustive `case event.kind`. The rest of this
guide covers code that uses `Terminal` / `AsyncTerminal` directly, reads keys
with the blocking or async wait procs, restores the terminal from a signal
handler, puts escape sequences into cell symbols, or checks the bytes celina
writes.

## Checklist

| If your code ... | Do this |
| --- | --- |
| has an exhaustive `case event.kind` | add an `InputClosed` branch ([1](#1-eventkindinputclosed)) |
| constructs `Terminal(lastBuffer: ...)` / `AsyncTerminal(lastBuffer: ...)` | use `newTerminal()` / `newAsyncTerminal()`, then assign ([2](#2-lastbuffer-is-an-accessor)) |
| constructs `AppState(forceNextRender: ...)` / `AsyncAppState(forceNextRender: ...)` | drop the field ([3](#3-appstateforcenextrender-is-removed)) |
| loops on `readKey` / `waitForKey` / `waitForKeyAsync` | leave the loop on `InputClosed` ([4](#4-reading-keys-after-stdin-ends)) |
| calls `draw(buffer, force = true)` after `resume` | drop `force` ([5](#5-suspend-and-resume)) |
| calls the free `clearScreen()` and then draws | use `terminal.clearScreen()` ([6](#6-clearing-the-screen)) |
| calls `restoreTerminal` from a signal handler | use `emergencyRestore` ([7](#7-signal-and-crash-hooks)) |
| calls `adoptLastBufferImpl` | assign or `swap` `lastBuffer` ([8](#8-adoptlastbufferimpl-is-deprecated)) |
| puts escape sequences into cell symbols | use `Style` and `hyperlink` instead ([9](#9-control-characters-in-cells)) |
| calls `makeCursorMoveSeq` | check the inputs ([10](#10-makecursormoveseq)) |
| compares the bytes celina writes | update the expected output ([11](#11-output-you-may-see-in-tests)) |

`clearLastBufferForResume` is removed too, but it used a private field, so code
outside the library could not call it.

## Breaking changes

### 1. `EventKind.InputClosed`

`InputClosed` is a new `EventKind` value: stdin has ended (`app < /dev/null`, a
drained pipe, a hung-up terminal on Linux), so no more input will arrive. An
exhaustive `case event.kind` without a branch for it no longer compiles.

```nim
# v0.13.0
case event.kind
of Key:
  handleKey(event.key)
of Mouse, Resize, Paste, FocusIn, FocusOut, Quit, Unknown:
  discard

# v0.14.0
case event.kind
of Key:
  handleKey(event.key)
of InputClosed:
  return erQuit # or discard to keep running
of Mouse, Resize, Paste, FocusIn, FocusOut, Quit, Unknown:
  discard
```

`App` / `AsyncApp` deliver it once, to the global `onEvent` handler only (not
to window handlers), and keep running unless the handler returns `erQuit`. Quit
when the app is useless without input; keep running when it also shows data
that does not come from the keyboard. A `case` with an `else` branch compiles
unchanged.

### 2. `lastBuffer` is an accessor

`Terminal.lastBuffer` and `AsyncTerminal.lastBuffer` are now procs, so they can
no longer be set in an object constructor. Reading, assigning and mutating
`terminal.lastBuffer` compile as before.

```nim
# v0.13.0
let terminal = Terminal(lastBuffer: previous)

# v0.14.0
let terminal = newTerminal()
terminal.lastBuffer = previous
```

`lastBuffer` is now only used while the screen is known: after a frame or a
`terminal.clearScreen()` went out in full. A new terminal starts unknown, and
`suspend`, `resume`, `invalidate`, `draw(buffer, force = true)` and a write
that stopped partway make it unknown again; a write that sent nothing keeps it
known, except in `drawWithCursorAdoptAsync`. `AsyncTerminal` behaves the same
with `suspendAsync`, `resumeAsync` and `drawAsync`. While it is unknown the next
`draw` or `render` is a full render, even if you assigned `lastBuffer`. In
v0.13.0 a non-empty `lastBuffer` always made the next `draw` a diff against it.
A test that presets `lastBuffer` to check diff output should draw one frame
first.

### 3. `AppState.forceNextRender` is removed

`App.state` and `AsyncApp.state` are private, so this only breaks code that
builds an `AppState` (or its alias `AsyncAppState`) itself. Remove the field. `App` / `AsyncApp` now record the clear they send
after setup and after a resize, so the frame that follows is a diff against the
cleared screen instead of a full render.

## Behaviour changes that may need code changes

### 4. Reading keys after stdin ends

In v0.13.0 the key readers returned `Unknown` (`none` for `readKeyInput` and
`pollKeyAsync`) forever once stdin ended, and `waitForKey` / `waitForKeyAsync`
(and so `waitForAnyKey` / `waitForAnyKeyAsync`) waited for a key that could
never arrive. They now report the end:

| Proc | At end of input |
| --- | --- |
| `readKey`, `pollKey` | `InputClosed` once, then `Unknown` |
| `readKeyInput` | `some(InputClosed)` once, then `none` |
| `waitForKey`, `waitForKeyAsync` | `InputClosed` on every call |
| `readKeyAsync` | `InputClosed` once, then `Unknown`; check `reader.isClosed` |
| `pollKeyAsync` | `some(InputClosed)` once, then `none` |
| `waitForAnyKey`, `waitForAnyKeyAsync` | `false`, as after a quit |

A loop that does not leave on `InputClosed` now spins at full speed instead of
sleeping inside the wait:

```nim
# v0.13.0
while true:
  let event = waitForKey()
  if event.kind == Quit:
    break
  handle(event)

# v0.14.0
while true:
  let event = waitForKey()
  if event.kind in {Quit, InputClosed}:
    break
  handle(event)
```

Use `waitForKey` instead of `waitForAnyKey` when quit and end of input must be
told apart.

Also:

- The blocking reader reads fd 0 with `read(2)` instead of C stdio, so it can
  be mixed with `pollKey` / `hasInput` / `pollEvents`. Bytes that Nim's `stdin`
  has buffered but your code has not read yet (e.g. after a `readLine`) are not
  seen by it, so do not mix the two.
- If you replace stdin's fd (e.g. with `dup2`), call `clearInputClosed()`
  afterwards; `Terminal.enableRawMode` does it for you. An `AsyncInputReader`
  stays closed, so create a new one with `newAsyncInputReader()`.
- `readKey` no longer documents an `IOError`; it never raised one.
- A 0-byte read on a live terminal (a cooked-mode Ctrl-D) does not end the
  input.

### 5. Suspend and resume

The v0.13.0 docs asked for `draw(buffer, force = true)` after `resume`. The
next `draw` after `resume` was already a full render, and still is: `resume`
now marks the screen unknown. `force` is redundant there; it still works.

```nim
# v0.13.0
terminal.suspend()
discard execShellCmd("vim notes.txt")
terminal.resume()
terminal.draw(buffer, force = true)

# v0.14.0
terminal.suspend()
discard execShellCmd("vim notes.txt")
terminal.resume()
terminal.draw(buffer)
```

`resume` keeps `lastBuffer` instead of replacing it with an empty buffer.
`app.resume()` / `app.resumeAsync()` without an earlier suspend no longer force
a full redraw.

### 6. Clearing the screen

The free `clearScreen()` writes to the screen without updating the terminal, so
the next `draw` diffs against content that is gone. This was already the case
in v0.13.0; v0.14.0 adds the methods that record the clear:

```nim
terminal.clearScreen()             # sync
await terminal.clearScreenAsync()  # async
```

After anything else writes to the screen behind celina's back (the free
`clearScreen()`, `clearLine`, `renderCell` or their `Async` variants, another
program), call `terminal.invalidate()` so the next frame is a full render.

### 7. Signal and crash hooks

The v0.13.0 docs called `app.restoreTerminal()` from a `setControlCHook`.
v0.14.0 adds `emergencyRestore` on `App`, `AsyncApp`, `Terminal` and
`AsyncTerminal` for that: while the app runs, it writes straight to the fd
instead of flushing C stdio, and first aborts an escape sequence a cut frame
left half-sent.
`restoreTerminal` still works. `installDefaultCrashGuard` already uses
`emergencyRestore`.

```nim
# v0.13.0
proc onCrash() {.noconv.} =
  app.restoreTerminal()
  quit(1)
setControlCHook(onCrash)

# v0.14.0
proc onCrash() {.noconv.} =
  app.emergencyRestore()
  quit(1)
setControlCHook(onCrash)
```

### 8. `adoptLastBufferImpl` is deprecated

It still works but warns. Assign `lastBuffer`, or `swap` it when the areas
match:

```nim
if terminal.lastBuffer.area == buffer.area:
  swap(terminal.lastBuffer, buffer)
else:
  terminal.lastBuffer = buffer
```

### 9. Control characters in cells

Cell symbols and hyperlink URLs are now sanitized, so text from a file, a paste
or the network cannot inject escape sequences:

- A cell symbol that contains a control (C0, DEL or C1) or is not well-formed
  UTF-8 becomes a single space. This covers `cell`, `[]=`, `setCell`, `fill`,
  `clear`, `merge`, `renderCell` and `renderCellAsync`, which wrote the symbol
  unchanged in v0.13.0.
- `setString` / `setRunes` already replaced C0 and DEL with one space each;
  they now do the same for C1, so the text keeps its columns.
- Controls are removed from hyperlink URLs; a URL that is not well-formed UTF-8
  or is longer than `MaxOscUrlLen` (2048 runes) is dropped and the text renders
  without a link.
- Window titles lose their controls and are cut to `MaxOscTitleLen` (512
  runes).

If you put escape sequences into a cell symbol for colours or links, the whole
symbol now becomes a single space. Use the `style` and `hyperlink` parameters
instead:

```nim
# v0.13.0
buffer[0, 0] = cell("\e[31mE\e[0m")

# v0.14.0
buffer[0, 0] = cell("E", style(Red))
buffer.setString(0, 1, "docs", hyperlink = "https://example.com")
```

`sanitizeCellSymbol` / `sanitizeHyperlink` apply the same filtering if you need
it elsewhere. The filtering assumes the terminal is in UTF-8 mode; run the app
in a UTF-8 locale.

### 10. `makeCursorMoveSeq`

It now returns `""` instead of an unchecked sequence (or an `IndexDefect`) for
an empty `direction`, `steps < 1`, a final byte outside `0x40..0x7E`, or, with
`steps == 1`, a `direction` that is not exactly `\e[` plus one final byte. Pass
the direction constants and put the count in `steps`:

```nim
# v0.13.0
makeCursorMoveSeq("\e[2A", 1)

# v0.14.0
makeCursorMoveSeq(CursorUpSeq, 2)
```

The library's own cursor helpers already do this.

### 11. Output you may see in tests

If your tests compare the bytes celina writes:

- After setup and after a resize, `App` / `AsyncApp` clear the screen with
  `\e[0m\e[2J` (previously `\e[2J`), and the frame that follows is a diff
  against the cleared screen.
- Full renders start with `\e[0m\e[2J` and skip default blank cells. This
  includes the full renders of `drawWithCursor` and its variants, which did not
  clear the screen in v0.13.0. `RckClearScreen` also sends `\e[0m` first.
- After a write that stopped partway, the bytes that follow start with CAN ST
  (`\x18\e\\`): right away if stdout takes them, else at the start of the next
  write. After a cut frame, OSC 8 and SGR resets follow it (and the end of
  synchronized output for a wrapped frame); after a cut frame or clear, the
  next frame is a full render.
- `resume` / `resumeAsync` send the same resets
  (`\x18\e\\\e]8;;\e\\\e[0m\e[?2026l`) before their first write.
- Sync writes go to fd 1 instead of `stdout.getFileHandle()`.

`run` / `runAsync` also reset `shouldQuit` when they end, so calling `run` again
after a quit starts a new loop instead of ending after its first tick.
